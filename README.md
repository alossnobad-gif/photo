# 自然图鉴

个人摄影图库、基础修图、物种图鉴与风光足迹平台。React + Vite 前端，Express 服务端；真实照片、收藏和任务保存在 `.data`。

最新需求和维护规则见 [产品文档](docs/product/README.md)。PRD、功能清单和迭代规范共同作为后续开发基线；下面的部署/历史说明如有差异，以最新产品文档及实际代码核对为准。

## 启动

需要 Node.js 22+。

```sh
cd /workspace/photo
npm ci --cache /workspace/.npm-cache
npm run dev
```

服务监听 `0.0.0.0:3000`。`npm run build` 构建；`npm start` 使用生产构建；`npm test` 验证首次解锁、重复保护及替换保留首次发现日期。

## 千问识别

在云环境设置中安全填写 `DASHSCOPE_API_KEY` 并重新启动服务。默认模型为 `qwen-vl-plus`，可通过 `QWEN_MODEL` 指定支持图片输入的千问模型。接口为中国区 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`；国际区密钥不能直接用于此接口。密钥只在服务端使用，不返回到浏览器。

缺少密钥时显示明确提示，并支持手动录入。照片发送到千问后产生候选结果，需要用户确认物种名称及学名才入库。不确定的识别结果需人工核实；稀有度是一般观测参考，不是保护等级。

## 收藏流程

上传 JPG/PNG/WebP（最大 50 MB）→识别或手动录入→确认→首次物种解锁。学名作为去重依据（忽略大小写及重复空格）；已有物种并排显示新旧照片，可保留或替换。替换保留原始 ID 和首次发现日期。`.data` 包含个人照片，请备份、保留。当前是单人云环境应用，无多用户登录系统。

## 网页识别设置

侧栏「识别设置」支持保存中国区 DashScope API Key 和视觉模型名称，保存后立即生效，无需重启。密钥输入留空会保留已有配置；填写则替换。接口只返回是否配置与模型名，不返回密钥。网页保存的配置优先于环境变量，保存在 `.data/recognition-settings.json`（权限 600），重启及更新代码后保留。该文件含密钥，不要上传 GitHub 或公开分享；备份 `.data` 时同样保护它。

当前单人部署依赖安全组限定访问来源；设置接口校验同源请求，但尚无账户登录。HTTP 不加密传输，请在可信网络使用并后续配置 HTTPS。保存成功不代表密钥权限、额度或模型调用已验证，应上传照片进行实际验证。

服务器更新（已安装 Node.js 22 并配置 nature-photo 服务）：

```sh
cd /opt/photo
git pull --ff-only origin main && npm ci && npm run build && npm test && systemctl restart nature-photo
```

更新不删除 `.data` 或 `/etc/nature-photo.env`。新增设置页在手机 390×844 上经系统 Chromium/Playwright 检查输入遮蔽、保存提交与状态更新（写入响应模拟）；服务端持久化及不返回密钥由独立测试验证。真实千问调用仍需用户密钥验证。

## 千问 AI 平台接入

`platform.qianwenai.com` 创建的密钥应选择「千问 AI 平台」，请求地址为用户提供的官方文档中的 `https://maas.qianwenaiapi.com/compatible-mode/v1/chat/completions`，图片示例模型为 `qwen3.8-max`。该平台与阿里云百炼为不同接口选项，不应混用密钥。切换平台时密钥留空保留原密钥，设置持久保存。旧配置继续使用 DashScope，需用户在设置中明确切换。只允许上述两个固定 HTTPS 目的地址。现有图片上传以 Base64 data URL 发送，用户文档示例只展示公网图片 URL；新平台真实调用与 Base64 支持尚待实际验证。

## 识别图片压缩

原始上传文件仍保存在 `.data/photos`，图库继续使用原图。调用模型前在内存中生成识别图片：自动校正 EXIF 方向，保持宽高比例，长边不超过 1600 像素，不放大小图，JPEG 质量 80，透明背景合成为白色。不裁剪主体；识别副本不额外写入磁盘。小图转换后若更大且不需要旋转，则保留原编码发送。使用 sharp，原生处理线程限制为 1；最大输入 8000 万像素。

测试照片 4000×3000 从 1,725,681 字节缩为 168,749 字节，原始字节未改变。压缩测试与既有设置/收藏测试共 7 项通过。服务器到模型的图片请求体积下降；手机上传原图的耗时及模型推理耗时并不保证同比下降。远处的小主体仍可能因缩图损失细节，尚未实现手动裁剪。

该更新新增 sharp 依赖，需要在拉取后运行 `npm ci`，测试通过再重启 `nature-photo`；前端未变更，无需重新构建。

## 模型请求超时

识别请求等待上限为 120 秒，回答上限 1200 tokens；超时、网络连接失败及不完整 JSON 分别显示明确提示，不自动重试产生额外调用。Nginx 应设置 `proxy_read_timeout 150s;`，避免在应用等待结束前关闭连接。既有 90 秒部署需要同步更新此值并经 `nginx -t` 后重载。延长等待不能保证模型提速或成功，需要在实际服务器上传图片复核。7 项既有测试通过，另以模拟上游 TimeoutError 验证实际识别路由返回 504、限制回答长度并保留原图。

## 解锁统计与分享

主页「探索成就」展示已解锁物种数、分类计数，以及常见、稀有、未知的分布。个人探索目标默认 100 种，可修改为 1–10000 的整数，保存在 `.data/exploration-goal.json`。没有完整物种目录，因此该进度为个人目标进度，不代表全球物种完成率，百分比最大 100%。

「分享图鉴」生成 1080×1440 PNG，包含统计、进度和最近解锁的最多 6 个物种照片及名称；不包含 API Key、服务器地址或 EXIF 信息。可下载图片，手机长按预览保存相册，并复制配文自行发布到小红书等平台。设备支持 Web Share 文件分享时显示「系统分享」；当前 HTTP 页面通常只能下载和复制，无平台自动发布。配文复制提供 HTTP 下的兼容方式与手动选择兜底。

构建及 8 项测试通过。系统 Chromium/Playwright 检查桌面 1440×1045、手机 390×844，统计显示、目标调整、分享图导出和配文复制；目标真实路由验证默认值、保存、磁盘持久化及非法值拒绝。截图及 PNG 导出在临时目录检查，未提交个人数据。

观测稀有度支持常见、稀有、未知，旧记录的少见自动兼容为稀有。保护等级独立记录（国家一级、国家二级、三有动物、地方重点保护等），默认未核实，由用户对照现行名录确认；统计和分享显示已记录的国家一级、二级数量。

## 离线保护名录与现有鸟类重新匹配

识别不再让模型猜测保护等级。应用携带 1,322 条离线候选记录（国保动物公开整理表 988 条，补充北京鸟类国保/三有数据）；并非完整官方现行名录，尚未逐项核对官方原件，植物保护名录未覆盖。数据出处、原文件、固定 Git 提交、原文件 SHA-256、采集日期和版本保存在 `data/catalogue`。保留 Birdle MIT 署名及许可，只提取物种名称、学名、等级与适用范围事实，不复制其照片和介绍。完整出处见 [名录说明](data/catalogue/README.md)。

严格匹配中文名（含明确旧名）、有数据的学名及分类。国保表优先于区域鸟类表；21 条来源冲突返回未核实，8 条“属/科/目所有种”不自动外推，61 条限定野外种群的记录不凭照片确定适用范围。不在数据中不代表没有保护，模型的不确定鉴定也不自动匹配。匹配结果标注“公开整理，待官方原件复核”。长尾鸭的先前手工“国家二级”断言已移除，目前数据匹配为三有动物候选。

主页点击“重新匹配现有鸟类”会串行处理现有鸟类，保存结果、原始收藏备份和变更报告到 `.data`，其他类别、照片、ID、首次发现日期及备注保持原值。未匹配或冲突的旧鸟类等级重置为未核实。重复操作没有变化时不重复备份。该功能不再次调用模型、不重新上传照片。`GET /api/protection-catalogue` 提供数据覆盖及来源摘要。

也可部署时离线匹配（需要先停止服务，避免并发写入）：

```bash
cd /opt/photo
npm run collection:rematch  # 预览数量，不写入
systemctl stop nature-photo
npm run collection:rematch -- --apply --service-stopped
systemctl start nature-photo
```

离线写入保留原收藏文件的所有者和权限，适用于 root 部署、naturephoto 运行服务的配置。匹配失败后也要重新启动服务；原记录备份可用于恢复。

维护端运行 `npm run catalogue:update` 可批量拉取来源、校验数据并生成离线表；需审查 Git 差异和冲突后发布。两份来源全部下载和校验成功才替换文件，失败保留已有数据。`npm run catalogue:build` 从本地来源快照重建，`npm run catalogue:check` 检查生成文件是否一致。生产服务器只拉取已审查的数据更新，识别时不依赖外部名录网络。后续拿到官方新版本后，统一转换来源快照即可，无需逐只写匹配代码。

### 编辑已保存物种

打开物种详情，点击“编辑物种资料”，可修改名称、学名、分类、观测稀有度、保护等级、介绍、栖息环境和备注。保留原照片、ID、首次发现日期，并检查学名重复。勾选“保留我手动核实的保护等级”后，普通读取不会覆盖选择；主动重新匹配鸟类仍会按候选名录更新。

### 风光足迹

侧栏“风光足迹”与物种图鉴独立，记录保存于 `.data/landscapes.json`，原照片仍在 `.data/photos/`。按城市／地区自动生成相册；未填写的进入“待整理”。同一地区允许多张照片，支持具体地点、拍摄日期、题材多选、感想、编辑、相册封面及 PNG 分享海报。风光不计入物种解锁数。

上传照片后可手动保存，或点击“AI 整理风光信息”使用当前已配置的千问视觉模型。识别使用同样的压缩和超时机制，生成标题、题材、景观描述和分享文案。城市／地标作为独立候选显示置信度和依据，需用户核实后填入；普通山水不推断城市，日期不交给模型猜测。若原图包含 EXIF，则自动读取拍摄日期与 GPS 坐标供参考；城市／地区与具体地点由用户确认填写，目前不请求外部地理编码服务。上传仍限制为 50 MB，JPG/PNG/WebP。

升级无需新增依赖或迁移已有收藏。更新代码后重新构建并重启 `nature-photo`；首次保存风光时创建数据文件。

### 照片拍摄日期

物种卡片、详情和探索记录展示原照片 EXIF `DateTimeOriginal` 的日期，不再用录入日期冒充拍摄日期。没有拍摄信息时显示“拍摄日期未记录”，上传和编辑时可补填。时间排序使用拍摄日期，未记录的排在末尾；原 `discovered` 录入时间仍保留。替换照片采用新照片的拍摄日期。

服务启动时自动为没有 `takenAt` 字段的历史记录从服务器原图补读一次（含已有风光记录）。写入前保存 `.data/collection.json.before-photo-dates-*` 等原始备份；已有日期（包括用户留空）不会被覆盖。失败会记入服务日志，不阻止网站启动。日期按相机记录原样展示，不进行跨时区日期换算。


### 后台识别队列

配置千问后，物种和风光照片在本地裁切、调整并上传后进入后台队列，界面立即返回，可继续提交下一张。队列逐张识别照片，任务保存在 `.data/recognition-queue.json`，关闭浏览器不影响任务；服务重启会重新处理未完成的识别。服务器只接收上传前处理后的照片。

侧栏“识别队列”展示排队、识别中、待确认、失败和已入库状态。模型返回的有效置信度须严格大于 0.85 才自动入库；85 分及以下、缺失置信度、不确定或资料不完整的结果需人工确认。模型置信度是自评值，不能作为物种鉴定保证。保护等级仍使用原有离线名录匹配。

同种照片不会自动替换现有图鉴，而会进入待确认；可编辑结果并明确勾选替换。识别失败可重试，重试沿用已上传照片。重复提交同一照片返回原有任务；入库时检查照片是否已存在，避免重启后重复保存。

队列任务可“放弃并删除”，页面内确认后删除任务和未被收藏引用的照片。识别中的任务会中止请求，迟到结果不会自动入库；入库保存中的任务需等保存完成后操作。已入库任务提供“删除队列记录”，不会删除图鉴、风光记录或照片。

### 批量上传

物种图鉴、识别队列和风光足迹提供批量上传入口，可多选 JPG/PNG/WebP，每张最大 50 MB。批量方式跳过裁切与调色，按顺序上传原照片并逐张提交后台队列，原照片 EXIF 日期和 GPS 由服务器读取。上传阶段须保持页面打开，入队后识别可在后台继续。

面板显示每张照片的状态和累计进度，支持停止后续上传、继续上传及单独重试失败项。某张上传或入队失败不会阻断后续照片；入队失败时保留已上传路径，重试不重复上传。单张上传仍支持本地裁切和照片调整。

### 图库与 RAW 修图

新默认页面“图库与修图”统一原片导入、RAW 显影预览、裁切、旋转翻转、基础调色、覆盖保存、删除照片、下载未编辑原件和图库选片识别。原件位于 `.data/library-originals/`，版本信息位于 `.data/library.json`，预览与成片仍在 `.data/photos/`。旧图鉴和风光照片启动时会自动索引进图库，不移动原文件。

图库单张导入支持 150 MB；A7R V 的 ARW 需要 LibRaw 0.21.4 或以上：运行 `bash scripts/install-raw-decoder.sh` 安装新版解码器并重启服务，Nginx 请求大小需改为 `151m`。已用真实 Nikon D2H NEF、索尼 A7R V 中尺寸和全尺寸 ARW 验证显影、原件哈希、拍摄日期、独立成片、图库选片入队和手机布局。其余 RAW 格式取决于 LibRaw 支持的相机型号。基础照片调整作用于显影后的 sRGB JPEG，不是完整的 16-bit RAW 编辑流水线。

侧栏“拍照识别”菜单已移除；图鉴、风光和批量上传窗口仍保留，并可直接从图库选片，无需重复上传。删除识别队列不会删除图库照片。同一照片可分别作为物种或风光任务入队。当前按个人长期使用设计，未启用多用户、收费或自动异地备份。详见 `docs/photo-library.md`。

A7R V 相机同时保存的 RAW＋JPG 可以同时或分别导入，日常可直接选 JPG，无需先显影 ARW。图库有 JPG 原片筛选、轻量缩略图、覆盖编辑，默认修图输出长边 4096 像素，可选择其他尺寸或裁切后原尺寸。修图保存直接覆盖当前照片，清理无其他图库引用的原件；删除图库照片会保留已入库的图鉴和风光记录。

风光地点候选即使标题置信度大于 85 分仍进入待确认。无地点候选的高置信度风光可自动入库至“待整理”。照片 EXIF 日期和 GPS 进入队列后保留，模型输出的日期、坐标不会覆盖元数据。地点候选是模型自评，当前未接入外部地理编码或地标检索。

风光页按已填写地点去重统计省份、城市和地标打卡点，未核实 AI 候选不参与计数。省份默认个人目标为 34 个省级行政区，城市 50、地标 100，可在页面调整，目标保存在当前浏览器。旧照片可编辑补充省份；北京、天津、上海、重庆可从城市字段归入省级统计。
