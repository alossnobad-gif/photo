# 迭代、回归及发布规范

更新：2026-10-14。适用于后续每次开发，不限于大版本。

## 修改前

1. 阅读 PRD、功能清单、已知问题和相关模块文档；检查 git status，不覆盖其他未提交工作。
2. 写明此次需求、影响的入口/字段/集合及不应改变的规则。短改动可在进度说明中记录，较大改动形成文档条目。
3. 同时追踪前端按钮 → 请求类型 → 队列持久化 → 模型回复 → 保存集合 → 图库状态。只改按钮文字不等于改了提交类型。
4. 数据修复先提供范围和预览；不能从照片标题猜出所有待删记录。迁移先备份，说明是否改原图、字段、来源和旧任务。

## 修改后必要验证

| 影响范围 | 必要验证 |
| --- | --- |
| 任意运行时代码 | npm test、npm run build，检查失败/跳过和 git diff --check |
| 提交/队列/入库 | 物种与风光各提交；高低置信度、.85 边界、重复物种确认、重试停止、重启恢复；最终集合和状态核对 |
| 图库/照片编辑 | RAW 条件允许时及 JPG 导入；中文名/EXIF；覆盖后 ID/路径/日期不变；跨集合引用展示；相关历史任务处理 |
| 删除/文件清理 | 记录存在/重复删除/被其他集合引用/进行中任务；确认具体删除对象；错误时保留数据，不用真实用户照片测试 |
| 预览/缓存/性能 | 用 .data 真实目录；接口 200、有效图像、缓存、编辑失效、原图完整；不只用无隐藏目录的临时路径 |
| 布局/导航 | 浏览器电脑约 1440 和手机约 390 宽；页面往返三次、弹窗滚动、竖图、按钮、空/错/加载状态 |
| 名录/分类 | 有来源版本、已知例子、别名/学名冲突、未知不猜、人工覆盖规则、现有数据预览及回滚 |
| 部署/权限 | 服务启动、鉴权、反向代理、缩略图、.data 权限；不复制临时目录权限 |
| 纯文档 | 文档链接、字段及代码事实核查；不为纯文字编辑反复跑无关测试 |

验证相关实际行为，不能只测试与实现相同的条件语句。新增缺陷增加能复现它的测试；现有自动测试没有覆盖的跨模块浏览器操作单独说明。未运行、失败、开发验证、线上验证分别记录。

## 数据保护和恢复

- .data 中的 JSON、照片、未编辑原件、设置和删除标记都属于持久化资产；不得随源码包覆盖。
- 发布运行时代码前按实际权限制作 .data 与环境配置备份，不输出密钥。备份必须可读、可校验并记录时间，照片量大时核对磁盘空间。建议另有异地副本；当前没有自动灾备。
- 只复制必需源码文件，文件模式明确；保留 /opt/photo、服务用户与数据目录的权限。记录上一可用提交。
- 本地提交和 Git 推送不是线上部署成功。用户手动部署后检查 service active、实际 API、登录和至少一次关键操作。
- 未改变数据格式的代码回退使用上一可用源码重新构建并重启；数据迁移不能靠 git revert 恢复，需停服务、恢复对应备份、校验引用后重启。不得把整个数据库恢复到旧版却忘记期间新增照片。
- 若检查发现记录丢失、类型串线、错误覆盖或删除引用照片，暂停该路径的新改动，保留现场和备份，先修复并核对数据，不叠加新功能。

## 文档维护

每次功能迭代更新功能清单和变更记录；业务规则改变更新 PRD。每累计五次功能迭代，或下次开发发现整体梳理已超过七天，核对所有模块、文档差异及已知问题。没有会话或定时调度时不承诺自动执行。

优先级：数据安全、错误修复、完整流程稳定性、性能、体验、新功能。不得为了小 UI 调整改写整个数据流。大型文件拆分和存储重构独立规划，先补关键集成验证再实施。
