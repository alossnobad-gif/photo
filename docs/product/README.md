# 产品文档与迭代基线

更新日期：2026-10-14。代码审查基线：`a4c2a92`；线上部署版本需在每次发布后单独确认。

- [PRD](PRD.md)：目标、完整流程、不可破坏的业务规则。
- [功能清单](FEATURES.md)：已实现、有限支持、待验证、未实现的能力与代码依据。
- [迭代与回归规范](ITERATION.md)：改动前检查、测试、数据保护、发布与回滚。
- [变更和问题记录](CHANGELOG.md)：需求变更、已知问题、发布证据。

这些文件记录产品事实，不代替服务器备份，不表示线上已经升级。

维护节奏：每次涉及功能、字段、入口或行为的迭代同步更新；每累计五次功能迭代，或下一次开发时发现距上次整体梳理超过七天，做一次完整核对。没有后台定时任务，未启动开发时不会自动整理。

已明确的需求以 PRD 为准；临时修复入口不能自动变成长期功能。发现文档与代码不同，先登记差异并核实，不能静默删除既有能力。后续用户明确修改需求时，同时更新规则和历史。
